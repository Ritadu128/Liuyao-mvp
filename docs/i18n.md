# 多语言维护规范

当前公开网站支持：

- `zh-CN`：简体中文（默认）
- `en-US`：英文

## 结构

- UI 文案：`client/src/i18n/messages.ts`
- 语言状态、持久化、HTML 语言属性：`client/src/i18n/I18nContext.tsx`
- 六十四卦显示名称与八卦名称：`client/src/i18n/hexagrams.ts`
- AI 解读目标语言：客户端随请求发送 `locale`，服务端在 `server/routers/reading.ts` 强制执行。

## 不得违反的规则

1. 公开页面不得直接新增用户可见的中文或英文字符串；应先在 `zhCN` 中增加翻译键，再为 `enUS` 提供完整翻译。
2. 不允许语言之间静默回退。缺少翻译必须在类型检查或测试阶段失败，不能在英文页面临时显示中文。
3. 排盘身份只使用卦序、爻码和六次投掷结果校验；翻译后的卦名只负责显示，不能参与排盘判断。
4. 英文 AI 解读不得包含中文字符。服务端会在流式输出阶段拒绝污染内容，并自动重试。
5. 中文经文是 AI 的内部可靠来源；英文界面不直接展示未翻译的中文经文。英文“卦象解读”由 AI 用英文解释来源含义。
6. 历史记录必须保存生成时的 `locale`，不同语言的历史在对应语言界面中显示，避免把旧中文解读混入英文页面。
7. 错误提示优先返回稳定错误代码，并根据请求 `locale` 输出对应语言；不得把服务端中文错误直接显示到英文界面。

## 上线前检查

至少运行：

```bash
pnpm check
pnpm vitest run client/src/lib/i18n.test.ts --config vitest.config.ts
pnpm test
```

`client/src/lib/i18n.test.ts` 会检查：

- 中文和英文语言包的键完全一致；
- 英文语言包没有中文字符；
- 六十四卦全部存在英文显示名称。

新增公开页面后，还应分别在中文和英文下检查首页、投掷、结果、历史、隐私政策、免责声明、手势错误和长图导出。
